# Segurança e comunicação de problemas

Desenvolvido com IA. As contribuições e correções precisam de revisão e testes,
independentemente da ferramenta usada para escrevê-las.

O CertBox processa chaves privadas localmente. Relatos públicos devem usar
arquivos fictícios ou instruções para reproduzir o problema com dados de teste.
Nunca anexe chaves reais, senhas ou arquivos de clientes.

Utilize o recurso de relato privado de vulnerabilidades do repositório, se
habilitado. Caso ele não esteja disponível, abra uma issue pedindo um canal de
contato seguro, sem publicar detalhes que permitam explorar o problema e sem
incluir dados sensíveis. O link de suporte é obtido do endereço único do projeto.

A versão publicada mais recente é a referência para correções. Versões históricas
são preservadas para consulta e não recebem manutenção separada automaticamente.

Uma assinatura digital ou a disponibilidade numa loja não substitui revisão de
código, atualização de dependências e testes. As entregas diretas pelo GitHub
podem ser executáveis sem assinatura; o hash SHA-256 permite comparar o arquivo
com o da versão publicada, mas não comprova, por si só, ausência de falhas.
